# Zenith CAD Kernel

**個人ひとりと AI が、18 日で書いた B-Rep CAD カーネルです。**

> **English summary** — Zenith is a from-scratch B-Rep CAD kernel written in Rust
> (~119,000 lines, 8 crates), built by **one person working with an AI assistant
> over 17 days** (2026-08-19 → 2026-09-04, 841 commits). It performs exact boolean
> operations on solids, reads and writes STEP, and tessellates to watertight meshes.
>
> **Every claim in this repository is backed by a re-runnable measurement.**
> `VERIFICATION_PLAYBOOK.md` tells you how to re-measure each one.
> `HANDOVER.md` records the **failed** hypotheses with their numbers, next to the
> successes — on 2026-09-04 alone, eight guesses were wrong and are written down.
>
> It is **not** a finished product and **not** a drop-in OCCT replacement.
> OCCT is used here as a **yardstick**, not a target.
> **What we want to share is the method.**

## いま何ができて、何ができないか

**できること**（すべて再測定できます。手順は
[`VERIFICATION_PLAYBOOK.md`](VERIFICATION_PLAYBOOK.md)）

- **厳密なブーリアン**——47 配置・141 演算で **135 成功・6 断り**（断りは
  すべて「答えが本当に非多様体だから」で、**未実装による断りは 0**）。
  B-Rep もメッシュも**非多様体 0**。**恒等式**（`|A∪B|+|A∩B| = |A|+|B|`）を
  41 配置で測って**破れ 0**、残差の最悪 **3.900e-8**
- **大きさの桁**——0.005 〜 100 倍で破れ 0
- **自分の出力を入力に戻す**——10 連鎖 30 演算すべて成功
- **STEP の読み書き**——OCCT が配る実物の `screw.step` が**読めて、切れて、
  恒等式が 3.845e-13 で閉じます**
- **水密なメッシュ**——自作の立体は **11 通りの刻み（4〜64）すべてで**穴 0・
  重なり 0。**読んだ `screw.step`・`linkrods.step` も 11 通りすべてで 0／0**

**できないこと**（隠しません）

- **測った刻みの外は、測っていません。** 上の「11 通り」は**常設検体の
  実測範囲**であって、**どんな刻みでも水密だという証明ではありません**
  ——`screw.step` は 24 分割だけを見ていた頃、**水密に見えて壊れていました**
- **`linkrods.step`（実物の STEP）は、まだ切れません。** 縫合で相手のいない
  稜が **和 46 / 差 46 / 積 40 本**残ります（**2026/09/07 に測り直して同じ
  数字**でした。初出は 09/06 で、同じ日に
  **含む／含まれる稜を刻む段**を入れて 47/47/40 から減りました。4-357）。**根まで
  測りました**（4-346、**4-351 で言い方を訂正しています**）——**交線と
  トリム境界が 1.1e-4 ですれ違い、それはファイル自身の粗さ 2.4e-4 より
  小さい**ので、**交わっているかどうかを、ファイルの精度では決められません**。
  **ファイルが壊れているのではありません**——共有する稜 94 本は、**自分が
  申告した粗さの中では、すべて両方の曲面に乗っています**（4-351）。
  **幅の話でもありません**——相手までの距離は **0 か 0.01 以上で、
  間が丸ごと空**です（4-291。幅を緩める手は 6 回とも外しました）。
  **残っているのは、書いていない機能**です（4-358、4-367）——**9 枚の面が
  交線を受け取って 1 本も使えていません**。**いちばん多い断り文は
  「その曲面が割れる形だと認識されていない」**です。**壁は 1 つ**で、**NURBS の面を
  割る道は「四辺形の円柱側面を、母線か円で切る」しかなく**、
  **切り欠きの入った面は割れません**。**しかもその認識器は、自分の
  ビルダーが作った持ち方しか受け付けません**——**読んだ 2 ファイルの
  曲面 37 枚のうち、当てはまるのは 0 枚**です（4-371）。
  **読んだファイル特有の問題でもありません**——**自作の立体の連鎖
  ブーリアンでも、同じ壁に当たります**（4-366）
- 球の極など、**まだ実装していない配置**があります

## OCCT との関係——物差しであって、目標ではありません

始めた頃は「OCCT を置き換える」という言い方をしていました。**いまは物差しとして
使っています。**

**OCCT が配る実物の STEP ファイルを読んで、切って、恒等式が閉じるか。**
これは自分で作った立体では絶対に出ない欠陥を出します——実際、この軸を開けてから
**継ぎ目の p-curve、内側の T 字、uv で潰れた三角形、閉じた輪、物差しの混在**と、
欠陥が出続けています。**打率がいちばん高い軸です。**

置き換えを名乗るには、まだ足りません。**足りない場所は、上に書いたとおりです。**

### いまの現在地点（上の要約より細かい話）

**数字の正は [`HANDOVER.md`](HANDOVER.md) です。** ここと上の要約は、
そこからの引き写しです——**食い違っていたら、`HANDOVER.md` を信じてください。**

**掃く軸は4本目まで来ています**——「置き方」（`contact_placement_probe`）、
「大きさの桁」（`scale_sweep_probe`）、「自分の出力を入力に戻す」
（`rechained_boolean_probe`）は枯れました。**4本目の「読んだ立体（STEP）を
切る」は着手済み**です（9-H の H8。検体は `reference/OCCT`、掃き出しは
`read_and_cut_probe`）。

2026/09/03 の時点で、**`screw.step` は H8 の目標を満たしています**——読めて、
切れて、**表示メッシュも結果も非多様体 0**、恒等式が **3.845e-13 / 3.899e-13**
で閉じます（4-290）。**表示メッシュは2ファイルとも穴 0・重なり 0** です
（14 → 0、34 → 0。4-286、4-288）。

**ただし、それは 24 分割での話でした。** 同じ日に刻みを振って測ったら、
`screw.step` は **8・12・24 では水密なのに、16・20・32・48 では壊れます**
（**2026/09/06 に全刻みで水密**。4-296、4-329、4-332、4-338）。**利用者は刻みを自分で選ぶ**ので、
1つの刻みだけを見るのは測り方の穴です。**刻みを振る門を足しました**
（`mesh_density_probe`。4-297、4-348）——**自作の立体は 11 通りの刻みすべてで水密**で、
壊れるのは**読んだファイルの、継ぎ目のある面だけ**です。

**`linkrods.step` はまだ断られます**——縫合で相手のいない稜が
**和 46 / 差 46 / 積 40 本**（2026/09/07 実測。**別々の稜**で数えた数で、
のべも同数です。合計 132 本）。**非多様体は 0 本**です——9/4 の一時期は
和に 9 本ありましたが、4-319 で消しました。**公差の問題ではない**ところまで測ってあります
——**幅を緩める手は 7 回とも外しています**（4-323、4-327、4-328、4-339、4-343、4-352、4-388）。
**7 回目だけは理由が違います**（4-388）——**1〜6 回目は「数字が 1 つも動かなかった」、
7 回目は「効いて、壊した」**。**受け入れは確かに 1 枚を止めており、緩めたら本当に
割れました**（当たり 38 → 39）。**それでも稜は 46/46/40 → 48/48/42 と増えます**
——**割れた面の相手が割れていないので、2 本余ります**。
**要るのは「もっと割ること」ではなく「両方の立体の面を、揃えて割ること」**です
（**ただしこれはこの実験の話で、既にある 132 本の説明ではありません**）。
また、
**相手までの距離は 0 か 0.01 以上で、間が丸ごと空**（4-291）。
**交線とトリム境界は 1.1e-4 ですれ違い、それはファイル自身の
粗さ 2.4e-4 より小さい**——**測っても決まりません**（4-346）。

**2026/09/07 に、途切れている端を全部分けました**（4-377、4-379、4-380）。
**24 個のうち 11 個は既存の稜の上に着地しており、13 個はどの稜からも
離れています**——そして**その 13 個は、13 個とも A の面のトリムの「外」・
B の面の「中」（例外なし）**でした。

> **交線が、切られる側の面からはみ出しています。**
> **「続きが作られていない」のではなく、その端は本来そこに無いもの**です。

**はみ出しは片側だけ**です——**交わると判定された 25 組のうち 9 組**で
**交線が A（読んだ立体）の囲みを 0.0697〜0.9407 はみ出し**、
**B（切り手）をはみ出す組は 0 組**（最大 1.8e-8）。

**切り詰める手はもう書いてあります**（`ZENITH_NURBS_CLIP=1`）——
**入れると離れている端が 13 → 3、相手のいない稜が 132 → 126** になります。
**それでも既定にしていません**——**入れると、通っていた連鎖ブーリアンが
2 つ断られる**からです（4-365、4-366）。

**そして 2026/09/07 に、その 6 本を測り直しました**（4-384）。
**直ったのではなく、縮んだのでした。**

| | 素 | **切り詰めあり** |
| :--- | ---: | ---: |
| 当たった割り | 38 | **30** |
| 1 枚も割らなかった交線 | 132 | **150** |
| **面片（和）** | **46** | **40** |
| 相手のいない稜（和） | 46 | 44 |
| **面片あたり** | **1.000** | **1.100** |

**面はより少なく割れています。** **稜が減ったのは、数える分母が
減ったから**です。

**面ごとに突き合わせると、決着しました**（4-387）——**減った 8 枚は、
8 枚とも B（切り手）の面**（B面0 が −3、B面1 が −5）で、
**A（読んだ立体）の面 16 枚は 1 枚も変わりません**。3 演算とも同じです。

> **はみ出しは A 側だけなのに、切り詰めた交線は A と B の両方を
> 割るのに使われます。** **片側のために切って、両側で使っています。**

**「下流を直せば既定にできる」という筋は消えました**——
**直す先の A に、効き目がありません。**

**直す先は、切る段ではなく割る段**です。

**残った 3 本のはみ出しも切ってみました**（4-381、4-382）——
**途切れている端は 3 → 0 になりましたが、相手のいない稜は 1 本も
動きません**。**その 3 本は、相手のいない稜を 1 本も作っていません
でした。** **「途切れている端を 0 にする」は、目的にできません。**

**断り文の数え方も違っていました**（4-383）。**割る道の断り文は
4 段の受け皿を `; ` で繋いだもの**で、**前の段が断っても次の段が割れば
通ります**——**最後の 1 つだけが決め手**です。全部を等しく数えて出した
筆頭（`Only recognized cylinder-side NURBS patches can be split`、126）は、
**決め手 0 件**でした。**交線ごとに数え直した本当の順位**は、
**面の途中で終わる切り口 63 本（48%）／平面の面 57 本（43%）／
穴のある面 12 本（9%）／認識器 0 本**です。

**そして、その 3 つはほぼ 1 つでした**（4-385）。**平面にも曲面と同じ受け皿を
付けて測ると、結果の数字は 1 つも動かない**（稜 46/46/40 のまま）一方で、
**平面の 57 本のうち 54 本が、曲面と同じ「境界まで届かない」へ合流**します。

| :--- | ---: | ---: |

| 穴のある面 | 12 | 9% |

**設計の判断は要りません**——`make_cylinder` は**円を4本の四半弧**で
持ちます。さらに、**少しでも割れた面は、どの鎖の段にも来ません**（4-315）。

**この軸は、開けてから 4-286〜4-315 で欠陥を出し続けています**——継ぎ目の
p-curve、内側の T 字、uv で潰れた三角形、閉じた1本の輪（3か所）、物差しの混在、
**内側の輪を丸ごと渡していたこと**（4-306）。**打率がいちばん高い軸です。**

**ただし、当たりも外れも多い軸です**——**9/4 だけで手を 7 つ外しました**。
入れる前に `HANDOVER.md` の 4-305〜4-315 を読んでください。**同じ道を
歩き直さないように、数字ごと残してあります。**

**閉じた式が無くても、恒等式なら測れます。** 2026/08/28 に直した誤答3件は
**3件とも恒等式でしか見えませんでした**——面は閉じ、非多様体でもなく、
内外判定も通ります（`HANDOVER.md` の 4-143〜4-145）。**形を見ても分かりません。**
